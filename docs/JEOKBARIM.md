# 적바림 설계

## 정체성
- 사이트 이름: 적바림 (순우리말: 나중에 참고하려고 간단히 글로 적어 둠). 기존 "1인 서점 / 몽상"을 대체.
- 성격: 책을 파는 서점이 아니라, 생각을 적고 적은 것 중 골라서 열어 두는 공개 노트장.
- 원칙: 기록이 먼저, 공개는 나중에 고르는 것. 모든 메모와 초안의 기본값은 비공개.

## 두 공간
1. 쓰는 공간 (관리자만)
   - 빠른 메모: 제목 없이 본문만 적고, 주제 버튼 하나로 분류(나중에 분류해도 됨). 휴대폰 우선 설계.
   - 노트 창고: 날짜별 메모 목록, 보기 필터(모든 노트/분류 전/공개한 것/키우는 중/주제별),
     여러 개 선택 → 공개하기, 주제 바꾸기, "묶어서 글 초안 만들기".
2. 보이는 공간 (방문자)
   - 상단 "최근 글": 긴 글만 매거진처럼 표지와 함께. 최신 글 하나는 크게(2:1:1 그리드).
   - "짧은 노트": 메모는 표지 없이 본문 그대로, 날짜·주제만 표시.
   - "책장": 독후감을 쓴 책 표지. 누르면 요약 창.
   - 표지 클릭 → 요약 창(모달): 세 줄 AI 요약, 이 글이 나온 메모, 전문 읽기, 같은 주제 더 보기.
   - 상단 메뉴: 전체 / 주제들 / 소개.

## 주제 (관리자 설정에서 편집 가능해야 함)
생각 · 일하며 배운 것 · 오늘의 배움 · 말씀 묵상 · 독서 · 상상

## 글의 종류
- 메모(note): 제목 없음, 짧음, 표지 없음.
- 긴 글(article): 제목 있음, 표지 있음, 발행 시 AI 요약 생성.

## 표지 규칙
- 본문에 이미지가 있으면 첫 이미지를 자동으로 표지로 사용.
- 없으면 주제 색 배경 위에 제목이 찍히는 자동 타이포 표지(이미지 파일 생성 없이 CSS로).
- 표지를 고르는 별도 단계는 만들지 않는다.

## AI 요약 규칙
- 방문자가 클릭할 때 생성하지 않는다. 발행할 때 한 번 생성해 DB에 저장.
- 발행 전에 요약을 보여주고 관리자가 수정할 수 있어야 한다.
- 기존 api/proofread.js 의 Claude 호출 방식과 ANTHROPIC_API_KEY 를 재사용.

## 관리자 설정 (/admin/settings)
여섯 묶음: 문구 / 주제 / 서재 주인 / 홈에 보일 것 / 색 / 글 템플릿.

- 문구: 제호, 한 줄 소개, 최근 글·책장 섹션 제목, 푸터 이름, 푸터 한 줄.
- 주제: 이름·짧은 이름·색·순서·추가·삭제. 표지 미리보기를 옆에 둔다.
  주제 이름은 posts.topic 에 글자 그대로 들어 있으므로, 이름을 바꾸면 그 주제의 글도
  함께 옮긴다. 저장 전에 몇 편이 바뀌는지 보여주고 확인을 받는다.
  주제를 지우면 그 글들은 '분류 전'으로 되돌린다.
- 서재 주인: 닉네임·한 줄 소개·사진. 소개 페이지 맨 위와 푸터에 보인다.
- 홈에 보일 것: 짧은 노트 / 책장 켬·끔 두 개.
  (섹션 순서 바꾸기는 두지 않는다. 홈은 시안의 2:1:1 고정 배치다)
- 색: 개별 색상만 고른다. 테마 프리셋은 두지 않고, 대신 "시안 색으로 되돌리기" 버튼을 둔다.
- 글 템플릿: 아래 참고.

정리한 옛 항목: 히어로 배경 이미지, 이름 위 영문 문구, 섹션 순서·숨김, 테마 프리셋,
SNS 더보기 섹션. (SNS 는 지금 운영하지 않는 채널이라 링크를 두지 않는다.
나중에 필요하면 설정에서 켜는 방식으로 되살린다)

## 글 템플릿
- 관리자가 템플릿을 만들고 저장, 글쓰기 화면에서 불러오기.
- 초기 템플릿: 질의응답(날짜 / Q. / A. / 근거), 독후감(책·저자 / 인상 깊은 문장 / 내 생각),
  묵상(본문 / 느낀 점 / 오늘의 적용). 설정의 "기본 템플릿 넣기"로 채운다.
- 저장 위치는 site_settings 의 key='templates' 에 JSON 배열. 테이블을 새로 만들지 않는다.
- 불러올 때 이미 쓴 본문이 있으면 덮어쓸지 묻는다.

## Claude 초안 입구
- 비밀 토큰(환경변수 DRAFT_API_TOKEN)으로 보호된 API.
- 이 API로 들어온 글은 무조건 published=false 로만 저장. 공개 전환은 불가능해야 한다.

## 모바일 우선
휴대폰(390px)을 기준으로 먼저 만들고, PC 는 넓혀서 대응한다.
- 홈(모바일): 대표 긴 글 1개를 크게 → "최근 글"은 가로로 넘기는 카드 →
  짧은 노트 → 책장(가로 스크롤).
- 홈(PC): 최근 글은 2:1:1 그리드.
- 상단 주제 메뉴는 가로로 넘기는 칩.
- 요약 창: 모바일은 아래에서 올라오는 시트, PC 는 가운데 모달.
- 요약 창에 공유하기 버튼 (Web Share API, 안 되는 브라우저는 링크 복사).

## 쓰는 공간 통합
- 노트 창고(/notes) 하나로 합친다. 옛 서재관리(/manage)는 없앴다.
- 긴 글을 누르면 글쓰기 수정 화면(/write/[id])으로 간다.
- 관리자 메뉴는 네 개: 적바림 · 노트 창고 · 글쓰기 · 설정. 회원관리는 설정 안으로.

## X 공유
- 노트 창고에서 메모 하나를 골라 "X에 공유"를 누르면 X 글쓰기 창(웹 인텐트)이 열린다.
- X API 는 쓰지 않는다. 인텐트 주소에 본문과 적바림 원문 링크를 채워 새 창으로 열 뿐이다.
- 누르면 그 메모는 적바림에서도 공개로 바뀐다. 먼저 한 번 확인을 묻는다.
- 280자를 넘으면 앞부분만 넣고 "…" 와 링크를 붙인다.
- 메모의 원문 주소는 긴 글과 같은 /posts/[id] 를 쓴다. 메모면 제목·표지 없이 본문만 보인다.

## 디자인
- 기존 따뜻한 우드 톤 유지 (배경 #faf6f0, 본문 #2c1a0e, 강조 #8b5e3c).
- 제목·본문 인용: Noto Serif KR / UI: IBM Plex Sans KR.
- 보조 글자는 #b09880 대신 #8a6f58 이상으로 진하게(대비 확보).
- 휴대폰 화면에서 깨지지 않을 것. 터치 영역 44px 이상.

## 안정성
- Supabase 무료 플랜은 활동이 없으면 프로젝트가 일시정지된다. (실제로 멈춘 적 있음)
- keep-alive: Vercel Cron 이 하루 한 번 /api/keep-alive 를 불러 DB 에 가벼운 조회를 날린다.
  CRON_SECRET 환경변수로 보호한다. (Vercel 이 Authorization: Bearer <CRON_SECRET> 를 붙여 호출)
- 공개 페이지(홈·글)는 캐시 + 재검증(5분). 글·설정을 바꾸면 revalidatePath 로 즉시 새로 만든다.
  DB 조회가 실패하면 예외를 던져 재검증을 실패시킨다. 그래야 "빈 페이지"가 캐시를 덮어쓰지 않고
  마지막으로 성공한 페이지가 계속 보인다. (lib/supabase.ts 의 assertDbOk)
- 캐시되는 페이지는 로그인 여부를 알 수 없으므로 공개 글(published + visibility='public')만 싣는다.
  루트 레이아웃에서 auth() 를 부르지 않는다. 부르면 모든 페이지가 매 요청 동적 렌더링된다.
  로그인 상태는 브라우저에서 SessionProvider 가 가져오고, 수정·삭제 버튼도 브라우저에서 판단한다.
  (실제 권한은 API 가 다시 검사한다)
- 관리자 화면(/manage, /admin, 글쓰기)은 캐시하지 않는다. 항상 지금 DB 상태를 본다.

## 하지 않을 것
- 약속·일정 메모 기능 (렉스에서 처리).
- 네이버 블로그 자동 게시.
