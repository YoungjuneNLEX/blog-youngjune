# 적바림 설계

## 정체성
- 사이트 이름: 적바림 (순우리말: 나중에 참고하려고 간단히 글로 적어 둠). 기존 "1인 서점 / 몽상"을 대체.
- 성격: 책을 파는 서점이 아니라, 생각을 적고 적은 것 중 골라서 열어 두는 공개 노트장.
- 화면 말은 **짧은 글 / 긴 글** 두 가지로만 부른다. (메모·노트·짧은 노트 같은 말은 쓰지 않는다)
  DB 의 kind('note'/'article')는 그대로 두고 화면 말만 다르다.
  '적바림'은 사이트 이름(제호)에만 쓴다. 메뉴 이름으로 쓰지 않는다.
- 원칙: 기록이 먼저, 공개는 나중에 고르는 것. 모든 짧은 글과 초안의 기본값은 비공개.

## 두 공간
1. 쓰는 공간 (관리자만)
   - **글쓰기**(/write): 짧은 글과 긴 글을 한 화면에서 쓴다. 아래 "글쓰기" 참고.
   - **글관리**(/notes): 쓴 글을 날짜별로 펼쳐 놓고 골라서 처리한다. 아래 "글관리" 참고.
   - 설정은 글관리 오른쪽 위 톱니바퀴(⚙)로 들어간다.
2. 보이는 공간 (방문자)
   - 홈 맨 위: 커버 이미지 + 서재 주인(사진·닉네임·한 줄 소개)과 긴 글·짧은 글 편 수.
     사진·닉네임을 누르면 소개(/about)로 간다.
   - 그 아래 "긴 글 / 짧은 글" 탭(첫 탭은 긴 글), 주제 고르기, 앨범형·목록형 전환, 카드 목록.
   - 긴 글은 표지와 함께, 짧은 글은 표지 없이 본문 그대로.
   - 표지 클릭 → 요약 창: 세 줄 AI 요약, 이 글이 나온 짧은 글, 전문 읽기, 같은 주제 더 보기.
   - 모바일 하단 고정 메뉴: **방문자 홈 · 주제 · 소개 / 관리자 홈 · 주제 · 글쓰기 · 글관리 · 소개**.
   - PC 상단: 제호(홈 링크) + 방문자 `주제 ▾ · 소개` / 관리자는 거기에 `글쓰기 · 글관리`.
     '주제 ▾'는 카테고리 화면을 연다.
   - 햄버거 메뉴는 없다. '전체' 메뉴도 없다(홈이 전체 주제다). 로그아웃은 설정 맨 아래에 있다.

## 주제 — 2단계 분류 (관리자 설정에서 편집)
- 대분류 아래 중분류를 둔다. **깊이는 2단계까지만**. 3단계는 mergeConfig 가 막는다
  (상위 분류가 또 상위 분류를 가지면 대분류로 올린다).
- 계층은 설정 JSON 안에서만 산다. `Topic.parentId` = 대분류의 id, 없으면 대분류.
  DB 를 바꾸지 않는다. posts.topic 에는 지금처럼 **주제 이름 하나**가 글자 그대로 들어간다.
- 글은 대분류에도 중분류에도 붙을 수 있다.
- **대분류를 고르면 그 대분류 글 + 모든 중분류 글**을 함께 보여 준다. /topics/[대분류] 도 같다.
- 중분류는 색을 비워 두면 대분류 색(바탕·글자)을 물려받는다.
- 대분류를 지우면 "중분류를 대분류로 올릴지 / 함께 지울지" 묻는다.
  글은 기존 규칙대로 '분류 전'으로 되돌아간다.
- 대분류 이름을 바꾸면 그 대분류에 직접 속한 글만 옮긴다. 중분류 글은 그대로.
- 기본값은 여섯 개 모두 대분류: 생각 · 일하며 배운 것 · 오늘의 배움 · 말씀 묵상 · 독서 · 상상.

## 카테고리 화면
- 하단 메뉴 '주제', 홈·주제 페이지의 '전체 주제 ▾', PC 상단 '주제 ▾' 가 같은 창을 연다.
- 모바일은 전체 화면(왼쪽 위 닫기 X, 제목 '카테고리'), PC 는 가운데 창.
- 맨 위 '전체 글 N', 그 아래 대분류 → 들여쓴 중분류, 오른쪽에 글 수.
- 누르면 그 분류의 글 목록(/topics/[이름])으로 간다. '전체 글'은 홈(전체 주제)으로 돌아간다.
- 지금 보고 있는 분류는 쪽빛 글자 + 연한 쪽빛 배경.
- 글 수는 GET /api/topic-counts 에서 받는다. **공개 글(published + visibility='public')만** 센다.
  5분 캐시. 대분류 수는 중분류 글까지 더한 값. 숫자를 못 받아도 목록은 그대로 보여 준다.
- 카테고리 단위 비공개(자물쇠)는 두지 않는다. 공개 여부는 글마다 정한다.

## 글의 종류
- 짧은 글(kind='note'): 제목 없음, 짧음, 표지 없음. 새로 쓰면 항상 비공개.
- 긴 글(kind='article'): 제목 있음, 표지 있음, 발행 시 AI 요약 생성.

## 표지 규칙
- 본문에 이미지가 있으면 첫 이미지를 자동으로 표지로 사용. 사진 위에는 글자를 얹지 않는다.
  (제목은 카드 아래에 따로 붙는다)
- 없으면 주제의 파스텔 바탕 위에 주제 이름과 제목이 찍히는 자동 타이포 표지
  (이미지 파일 생성 없이 CSS로).
- 표지를 고르는 별도 단계는 만들지 않는다.

## AI 요약 규칙
- 방문자가 클릭할 때 생성하지 않는다. 발행할 때 한 번 생성해 DB에 저장.
- 발행 전에 요약을 보여주고 관리자가 수정할 수 있어야 한다.
- 기존 api/proofread.js 의 Claude 호출 방식과 ANTHROPIC_API_KEY 를 재사용.

## 관리자 설정 (/admin/settings)
여섯 묶음: 문구 / 주제 / 서재 주인 / 홈에 보일 것 / 색 / 글 템플릿.

- 문구: 제호, 검색 설명문, 푸터 이름, 푸터 한 줄.
- 주제: 이름·짧은 이름·상위 분류·바탕색·글자색·순서·추가·삭제. 표지 미리보기를 옆에 둔다.
  목록은 대분류 아래 중분류가 들여쓰기로 보인다. 순서 바꾸기는 같은 상위 분류 안에서만.
  중분류로 내리면 색이 비워져 대분류 색을 따른다.
  주제 이름은 posts.topic 에 글자 그대로 들어 있으므로, 이름을 바꾸면 그 주제의 글도
  함께 옮긴다. 저장 전에 몇 편이 바뀌는지 보여주고 확인을 받는다.
  주제를 지우면 그 글들은 '분류 전'으로 되돌린다.
- 서재 주인: 닉네임·한 줄 소개·사진·홈 커버 이미지.
  홈 맨 위 커버와 소개 페이지 맨 위, 푸터에 보인다. 커버를 비우면 옅은 단색이 깔린다.
- 홈에 보일 것: "짧은 글 탭" 켬·끔 하나.
  끄면 홈·주제 페이지에서 탭이 사라지고 긴 글만 보인다.
  (설정 키 이름 showShortNotes 는 저장된 설정과 맞추려고 그대로 둔다.
  섹션 순서 바꾸기는 두지 않는다. 홈은 시안 고정 배치다)
- 색: 개별 색상만 고른다. 테마 프리셋은 두지 않고, 대신 "쪽빛 색으로 되돌리기" 버튼을 둔다.
  이 버튼은 사이트 색과 주제의 바탕·글자색만 되돌린다.
  주제 이름·짧은 이름·순서·상위 분류와 문구·서재 주인·템플릿은 건드리지 않는다.
  되돌리는 규칙:
    · 이름이 기본 주제와 같은 대분류 → 그 기본 짝.
    · 이름이 다른 대분류 → 파스텔 여섯 짝을 순서대로, 다른 대분류가 쓴 짝은 피해서.
    · 중분류 → 색을 비워 대분류 색을 물려받게.
  누르면 바로 바꾸지 않고 "주제 N개의 색이 이렇게 바뀝니다" 미리보기를 먼저 보여 준다.
- 글 템플릿: 아래 참고.
- 맨 아래에 로그아웃 버튼. 위쪽 '← 글관리' 로 돌아간다.

정리한 옛 항목: 히어로 배경 이미지, 이름 위 영문 문구, 섹션 순서·숨김, 테마 프리셋,
SNS 더보기 섹션, 책장 켬·끔과 책장 페이지 제목, 전체 페이지 제목. (SNS 는 지금 운영하지 않는 채널이라 링크를 두지 않는다.
나중에 필요하면 설정에서 켜는 방식으로 되살린다)

## 글 템플릿
- 관리자가 템플릿을 만들고 저장, 글쓰기 화면에서 불러오기.
- 초기 템플릿: 질의응답(날짜 / Q. / A. / 근거), 독후감(책·저자 / 인상 깊은 문장 / 내 생각),
  묵상(본문 / 느낀 점 / 오늘의 적용). 설정의 "기본 템플릿 넣기"로 채운다.
- 저장 위치는 site_settings 의 key='templates' 에 JSON 배열. 테이블을 새로 만들지 않는다.
- 불러올 때 이미 쓴 본문이 있으면 덮어쓸지 묻는다.

## Claude 초안 입구
- 보류 — 외부에서 초안을 넣을 일이 생기면 만든다. 만들 때는 5단계 계획의
  네 겹 방어(엔드포인트·표식·앱·DB 트리거) 설계를 따른다.
- 지금은 초안을 앱 안에서 만든다. 아래 "묶어서 긴 글 초안 만들기" 참고.

## 묶어서 긴 글 초안 만들기
- 글관리의 **짧은 글** 탭에서 짧은 글 여러 개를 골라 누르면 Claude 가 긴 글 초안 한 편으로 엮는다.
- 템플릿을 고를 수 있다(안 고르면 자유 형식). 고른 템플릿의 뼈대를 따라 쓴다.
- 원본 짧은 글은 그대로 남는다. 지우거나 옮기지 않는다.
- 한 번에 20개, 본문 합계 20,000자까지.
- 만들어진 글은 published=false 초안. 주제는 고른 짧은 글에서 가장 많은 주제를 쓴다.
- posts.source_note_ids 에 밑이 된 짧은 글 아이디를 적어 둔다.
  글관리에서는 "긴 글 초안으로 자람"으로 보이고, 방문자 요약 창에서는
  "이 글이 나온 짧은 글"로 보인다. 단, 공개된 것만 보인다.
- 만든 뒤 긴 글 수정 화면(/write/[id])으로 넘어간다. 발행은 평소처럼 거기서 한다.

## 모바일 우선
휴대폰(390px)을 기준으로 먼저 만들고, PC 는 폭만 넓혀서 대응한다.
- 홈(모바일): 커버+서재 주인 → 긴 글/짧은 글 탭 → 주제 고르기 + 앨범형·목록형 전환 →
  카드 목록 → 하단 고정 메뉴.
- 홈(PC): 같은 차례. 앨범형만 2열에서 3열로 넓어지고, 하단 고정 메뉴 대신 상단 메뉴를 쓴다.
- 앨범형: 표지 200px 2열, 표지 아래 제목과 "날짜 · 주제".
- 목록형: 날짜·읽는 시간 / 제목 / 요약 첫 줄 + 오른쪽 88px 네모 표지.
- 카테고리 화면: 모바일은 전체 화면, PC 는 가운데 창.
- 요약 창: 모바일은 아래에서 올라오는 시트, PC 는 가운데 모달.
- 요약 창에 공유하기 버튼 (Web Share API, 안 되는 브라우저는 링크 복사).
- 검색은 아직 만들지 않는다. 시안의 돋보기 자리는 비워 둔다.

## 글쓰기 (/write)
- '글쓰기' 버튼 하나. 예전 빠른 메모(/memo)와 글쓰기를 한 화면으로 합쳤다.
  /memo 는 /write 로 넘어간다. 휴대폰 홈 화면 아이콘(PWA)도 /write 로 열린다.
  (아이콘의 id 는 예전 그대로 둬서 이미 추가해 둔 아이콘이 다른 앱으로 바뀌지 않는다)
- 열자마자 본문 입력칸에 커서. 맨 위에 **[짧은 글 | 긴 글]** 전환. 기본은 짧은 글.
- **짧은 글**: 본문 + 주제만. 항상 비공개로 저장한다(기록이 먼저, 공개는 글관리에서).
  입력칸 아래에 '오늘 쓴 짧은 글' 목록.
- **긴 글**로 바꾸면 제목·템플릿·주제·표지·세 줄 요약 만들기·공개 설정이 펼쳐진다.
  쓰던 본문은 그대로 따라간다. 긴 글에서 짧은 글로 돌아갈 때는 제목·서식이 사라진다고 한 번 묻는다.
- 긴 글 저장은 임시저장(비공개) / 발행하기. 책 제목·카테고리·태그·책 소개 문구·예약 발행은 없앴다.
  (예약 발행은 화면에만 있고 서버가 받지 않던 칸이었다. 책장을 없애면서 책 제목도 필요 없어졌다)
- 기존 글 고치기는 /write/[id]. 그 글의 종류(짧은 글/긴 글)로 열린다. 종류는 거기서 바꾸지 않는다.
- 짧은 글은 관리자만 쓴다. 관리자가 아닌 글쓴이에게는 긴 글만 보인다.

## 글관리 (/notes)
- 이름은 글관리, 주소는 /notes 그대로(관리자만 쓰는 화면이라 주소를 흔들지 않는다).
- 맨 위 탭 **[짧은 글 | 긴 글]**. 탭마다 같은 필터(모두·분류 전·공개한 것·나만 보기·주제별)를 쓴다.
  주제별은 대분류를 고르면 중분류 글도 함께 나온다.
- **짧은 글 탭**: 공개하기 · 나만 보기로 · 주제 바꾸기 · X 공유 · 묶어서 긴 글 초안 만들기 · 삭제.
  각 줄의 '고치기'는 /write/[id] 로 간다.
- **긴 글 탭**: 줄을 누르면 /write/[id] 로 수정. 여러 개 골라 공개 / 나만 보기 · 주제 바꾸기 · 삭제.
- 오른쪽 위에 글쓰기 버튼과 톱니바퀴(⚙, 설정). 설정 맨 아래에 로그아웃이 있다.

## 책장
- 지금은 두지 않는다. /bookshelf 와 메뉴·설정의 책장 항목을 없앴다. (/bookshelf 는 홈으로 넘어간다)
- books 테이블과 데이터, /api/books 는 지우지 않고 그대로 둔다. 나중에 되살릴 수 있게.

## X 공유
- 글관리의 짧은 글 탭에서 짧은 글 하나를 골라 "X에 공유"를 누르면 X 글쓰기 창(웹 인텐트)이 열린다.
- X API 는 쓰지 않는다. 인텐트 주소에 본문과 적바림 원문 링크를 채워 새 창으로 열 뿐이다.

- 짧은 글의 원문 주소는 긴 글과 같은 /posts/[id] 를 쓴다. 짧은 글이면 제목·표지 없이 본문만 보인다.

## 안정성
- Supabase 무료 플랜은 활동이 없으면 프로젝트가 일시정지된다. (실제로 멈춘 적 있음)
- keep-alive: Vercel Cron 이 하루 한 번 /api/keep-alive 를 불러 DB 에 가벼운 조회를 날린다.
  CRON_SECRET 환경변수로 보호한다. (Vercel 이 Authorization: Bearer <CRON_SECRET> 를 붙여 호출)
- 공개 페이지(홈·글)는 캐시 + 재검증(5분). 글·설정을 바꾸면 revalidatePath 로 즉시 새로 만든다.
  DB 조회가 실패하면 예외를 던져 재검증을 실패시킨다. 그래야 "빈 페이지"가 캐시를 덮어쓰지 않고
  마지막으로 성공한 페이지가 계속 보인다. (lib/supabase.ts 의 assertDbOk)
- 캐시되는 페이지는 로그인 여부를 알 수 없으므로 공개 글(published + visibility='public')만 싣는다.
  루트 레이아웃에서 auth() 를 부르지 않는다. 부르면 모든 페이지가 매 요청 동적 렌더링된다.
  로그인 상태는 브라우저에서 SessionProvider 가 가져오고, 수정·삭제 버튼도 브라우저에서 판단한다.
  (실제 권한은 API 가 다시 검사한다)
- 관리자 화면(글관리 /notes, /admin, 글쓰기 /write)은 캐시하지 않는다. 항상 지금 DB 상태를 본다.
