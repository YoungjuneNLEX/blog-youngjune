# 적바림 설계

## 정체성
- 사이트 이름: 적바림 (순우리말: 나중에 참고하려고 간단히 글로 적어 둠). 기존 "1인 서점 / 몽상"을 대체.
- 성격: 책을 파는 서점이 아니라, 생각을 적고 적은 것 중 골라서 열어 두는 공개 노트장.
- 화면 말은 **짧은 글 / 긴 글** 두 가지로만 부른다. (메모·노트·짧은 노트 같은 말은 쓰지 않는다)
  DB 의 kind('note'/'article')는 그대로 두고 화면 말만 다르다.
  '적바림'은 사이트 이름(제호)에만 쓴다. 메뉴 이름으로 쓰지 않는다.
- 글을 묶는 말은 **서재 / 시리즈** 두 가지다. 서재는 큰 갈래, 시리즈는 서재 안의 연재 묶음. (아래 "서재와 시리즈")
- 원칙: 기록이 먼저, 공개는 나중에 고르는 것. 짧은 글과 초안의 기본값은 비공개. 적을 때 공개를 고를 수도 있다(글쓰기의 '공개 + X').

## 두 공간
1. 쓰는 공간 (관리자만)
   - **글쓰기**(/write): 짧은 글과 긴 글을 한 화면에서 쓴다. 아래 "글쓰기" 참고.
   - **글관리**(/notes): 쓴 글을 날짜별로 펼쳐 놓고 골라서 처리한다. 아래 "글관리" 참고.
   - 설정은 글관리 오른쪽 위 톱니바퀴(⚙)로 들어간다.
2. 보이는 공간 (방문자)
   - 홈 맨 위: 커버 이미지 + 서재 주인(사진·닉네임·한 줄 소개)과 긴 글·짧은 글 편 수.
     사진·닉네임을 누르면 소개(/about)로 간다.
   - 그 아래 "긴 글 / 짧은 글" 탭(첫 탭은 긴 글), 서재 고르기, 앨범형·목록형 전환, 카드 목록.
   - 긴 글은 표지와 함께, 짧은 글은 표지 없이 본문 그대로.
   - 표지 클릭 → 요약 창: 세 줄 AI 요약, 이 글이 나온 짧은 글, 전문 읽기, 같은 서재·시리즈 더 보기.
   - 모바일 하단 고정 메뉴: **방문자 홈 · 서재 · 소개 / 관리자 홈 · 서재 · 글쓰기 · 글관리 · 소개**.
   - PC 상단: 제호(홈 링크) + 방문자 `서재 ▾ · 소개` / 관리자는 거기에 `글쓰기 · 글관리`.
     '서재 ▾'는 서재 화면을 연다.
   - 햄버거 메뉴는 없다. '전체' 메뉴도 없다(홈이 전체 서재다). 로그아웃은 설정 맨 아래에 있다.

## 서재와 시리즈 — 2단계 분류 (관리자 설정에서 편집)
화면 말은 **서재 / 시리즈** 두 가지다. ('주제·카테고리·분류'라는 말은 화면에서 쓰지 않는다. 단, '분류 전'은 그대로 쓴다)
- **서재** = 큰 갈래(예전 대분류), **시리즈** = 서재 안의 연재 묶음(예전 중분류). **깊이는 2단계까지만**.
  3단계는 mergeConfig 가 막는다(시리즈가 또 시리즈를 가지면 서재로 올린다).
- 계층은 설정 JSON 안에서만 산다. `Topic.parentId` = 서재의 id, 없으면 서재. DB 를 바꾸지 않는다.
  posts.topic 에는 지금처럼 **이름 하나**가 글자 그대로 들어간다.
  글에 시리즈가 있으면 시리즈 이름, 없으면 서재 이름, 둘 다 없으면 비어 있다('분류 전').
- 이름은 서재·시리즈를 통틀어 겹치지 않는다. posts.topic 이 이름만 담기 때문이다.
  같은 서재 안에서 같은 이름을 쓰면 새로 만들지 않고 있던 시리즈를 고른다. 다른 곳과 겹치면 막고 이유를 보여 준다.
- **서재를 고르면 그 서재 글 + 모든 시리즈 글**을 함께 센다(편수·서재 화면의 숫자). 서재 페이지의 목록은 아래 "읽기" 참고.
- 시리즈는 색을 비워 두면 서재 색(바탕·글자)을 물려받는다.
- 서재를 지우면 "시리즈를 서재로 올릴지 / 함께 지울지" 묻는다. 글은 '분류 전'으로 되돌아간다.
- 서재 이름을 바꾸면 그 서재에 직접 속한 글만 옮긴다. 시리즈 글은 그대로.
- 기본값은 여섯 개 모두 서재: 생각 · 일하며 배운 것 · 오늘의 배움 · 말씀 묵상 · 독서 · 상상.
- 글쓰기에서 시리즈를 새로 만들면 설정에 바로 저장된다(POST /api/topics, 관리자만). 새 시리즈는 '연재로 보기'가 켜진 채로 생긴다.
  설정 화면이 오래 열려 있어도 그 사이 만든 시리즈의 글이 '분류 전'으로 가지 않도록,
  설정 저장은 화면이 알고 있던 목록(knownTopicIds)에 없는 기존 항목을 지우지 않는다.

## 서재 화면
(예전 카테고리 화면. 하단 메뉴 '서재', 홈·서재 페이지의 '전체 서재 ▾', PC 상단 '서재 ▾' 가 같은 창을 연다)
- 모바일은 전체 화면(왼쪽 위 닫기 X, 제목 '서재'), PC 는 가운데 창.
- 맨 위 '전체 글 N', 그 아래 서재 → 들여쓴 시리즈, 오른쪽에 글 수.
  소개글이 있는 서재·시리즈는 이름 아래에 한 줄로 흐리게 보인다.
- 누르면 그 곳의 글 목록(/topics/[이름])으로 간다. '전체 글'은 홈(전체 서재)으로 돌아간다.
- 지금 보고 있는 곳은 쪽빛 글자 + 연한 쪽빛 배경.
- 글 수는 GET /api/topic-counts 에서 받는다. **공개 글(published + visibility='public')만** 센다.
  5분 캐시. 서재 수는 시리즈 글까지 더한 값. 숫자를 못 받아도 목록은 그대로 보여 준다.
- **공개 글이 한 편도 없는 시리즈는 방문자 화면에서 숨긴다**(만들어 놓고 안 쓴 시리즈, 오타로 만든 시리즈가 빈 책처럼 보이지 않게).
  지금 그 시리즈를 보고 있으면 예외로 보인다. 숫자를 끝내 못 받으면 숨길 근거가 없으므로 전부 보여 준다.
  관리자 화면(글쓰기·글관리·설정)에서는 빈 시리즈도 그대로 보인다.
- 서재·시리즈 단위 비공개(자물쇠)는 두지 않는다. 공개 여부는 글마다 정한다.

## 읽기 — 서재 페이지, 시리즈 페이지, 연재
계층과 마찬가지로 설정 JSON 의 Topic 안에서만 산다. DB 를 바꾸지 않는다.
- **소개**: Topic 의 `description`(소개글)·`coverUrl`(대표 이미지). 둘 다 선택.
  - 페이지 맨 위에 소개 카드: 대표 이미지 · 이름 · 소개글 · 글 N편 · 정렬 전환.
    시리즈 페이지는 이름 위에 `서재 >` 가 붙는다.
  - 대표 이미지가 없으면 그 곳에서 **가장 오래된 공개 긴 글 중 사진이 있는 것**의 표지,
    그것도 없으면 서재 색 타이포 표지.
  - **소개글이 비어 있으면 카드를 아예 숨기고** 아래만 보인다. 이때 정렬 전환은 목록 위 줄에 따로 둔다.
  - 소개글·대표 이미지는 상속하지 않는다. 시리즈가 비어 있으면 서재 소개가 있어도 카드를 숨긴다.
  - 글 N편은 그 곳에 속한 공개 글(긴 글+짧은 글) 수. 서재는 시리즈 글을 포함한다.
- **서재 페이지**(/topics/[서재]): 위에서 아래로
  1. 서재 소개(있으면)
  2. **시리즈 줄** — 표지·이름·편수 카드를 가로로 밀어 본다. 누르면 /topics/[시리즈]. 공개 글이 없는 시리즈는 숨긴다.
     시리즈 카드 표지는 시리즈 대표 이미지 → 가장 오래된 공개 긴 글의 사진 → 서재 색 타이포 표지.
  3. **서재에 바로 속한 글** 목록(시리즈를 거치지 않은 글). 긴 글/짧은 글 탭과 앨범형·목록형은 그대로.
  서재에 바로 속한 글이 없고 보일 시리즈가 있으면 목록 칸을 안내문 없이 통째로 숨긴다.
  (시리즈도 글도 없으면 평소처럼 '글이 없습니다' 안내를 둔다)
- **시리즈 페이지**(/topics/[시리즈]): 소개 카드 → 그 시리즈의 글 목록. 연재로 보기·N화·이전/다음 글이 여기서 일한다.
- **'AI로 소개글 초안 만들기'**(설정, 관리자 전용): 설정에 *저장된* 그 곳의 공개 긴 글
  (서재는 시리즈 글 포함, 최근 20편)의 제목과 세 줄 요약(없으면 앞부분)을 모아
  2~3문장 초안을 만들어 칸에 채운다. 저장은 관리자가 고친 뒤 직접 한다.
  방문자 화면에서는 AI 를 부르지 않는다. (POST /api/topic-intro, 모델·방식은 /api/summary 와 같다)
- **연재로 보기**: Topic 의 `series`. 켜면 그 페이지가 **처음부터**(오래된 글이 위)로 열린다.
  - 서재를 켜면 시리즈가 따라간다. 시리즈는 `서재를 따름 / 켬 / 끔` 중에서 따로 정한다.
  - 페이지에 **최신순 | 처음부터** 전환이 있다. 긴 글 탭에만 적용하고, 짧은 글은 늘 최신순이다.
    홈(전체 서재)에는 두지 않는다 — 홈은 최근 글만 받아 두어서 '처음부터'가 틀린 결과를 보이기 때문이다.
  - 정렬 기준은 created_at, 공개 글만. 전환은 브라우저에서 하므로 페이지 캐시 규칙은 그대로다.
- **이전 글 / 다음 글**: 긴 글 상세 맨 아래. 같은 곳(글에 붙은 이름 그대로) 안의 공개 긴 글을
  created_at 순서로, 제목과 함께. 짧은 글 상세에는 두지 않는다.
  연재로 보는 곳이면 상세 위쪽에 `N화`, 이전/다음 칸에도 N화, 요약 창에는 `연재 N번째 글`.
  - N 은 **그 이름에 붙은 공개 긴 글 중 몇 번째**다. 서재 글과 시리즈 글은 따로 센다.
  - 번호 계산은 lib/series.ts. 연재로 보는 곳이 있을 때만 가벼운 조회 한 번(id·topic·created_at)을 하고,
    실패하면 예외를 던진다(assertDbOk).

## 글의 종류
- 짧은 글(kind='note'): 제목 없음, 짧음, 표지 없음. 새로 쓰면 기본은 비공개(적을 때 '공개 + X'를 고르면 공개).
- 긴 글(kind='article'): 제목 있음, 표지 있음, 발행 시 AI 요약 생성.

## 표지 규칙
- 본문에 이미지가 있으면 첫 이미지를 자동으로 표지로 사용. 사진 위에는 글자를 얹지 않는다.
  (제목은 카드 아래에 따로 붙는다)
- 없으면 서재의 파스텔 바탕 위에 서재(시리즈) 이름과 제목이 찍히는 자동 타이포 표지
  (이미지 파일 생성 없이 CSS로).
- 표지를 고르는 별도 단계는 만들지 않는다.

## AI 요약 규칙
- 방문자가 클릭할 때 생성하지 않는다. 발행할 때 한 번 생성해 DB에 저장.
- 발행 전에 요약을 보여주고 관리자가 수정할 수 있어야 한다.
- 기존 api/proofread.js 의 Claude 호출 방식과 ANTHROPIC_API_KEY 를 재사용.

## 관리자 설정 (/admin/settings)
여섯 묶음: 문구 / 서재와 시리즈 / 서재 주인 / 홈에 보일 것 / 색 / 글 템플릿.

- 문구: 제호, 검색 설명문, 푸터 이름, 푸터 한 줄.
- 서재와 시리즈: 이름·짧은 이름·소속 서재·바탕색·글자색·소개글·대표 이미지·연재로 보기·순서·추가·삭제.
  표지 미리보기를 옆에 둔다. 대표 이미지는 /api/upload 를 쓴다. 소개글 옆에 'AI로 소개글 초안 만들기'.
  목록은 서재 아래 시리즈가 들여쓰기로 보인다(관리자 화면이라 빈 시리즈도 보인다). 순서 바꾸기는 같은 서재 안에서만.
  '+ 서재 추가', 서재마다 '+ 시리즈 추가'(색을 비우고 연재로 보기를 켠 채로 생긴다).
  시리즈로 내리면(소속 서재를 고르면) 색이 비워져 서재 색을 따른다.
  이름은 posts.topic 에 글자 그대로 들어 있으므로, 이름을 바꾸면 그 서재·시리즈의 글도
  함께 옮긴다. 저장 전에 몇 편이 바뀌는지 보여주고 확인을 받는다.
  지우면 그 글들은 '분류 전'으로 되돌린다.
- 서재 주인(사이트 주인의 프로필. 위의 '서재'와 다른 뜻): 닉네임·한 줄 소개·사진·홈 커버 이미지.
  홈 맨 위 커버와 소개 페이지 맨 위, 푸터에 보인다. 커버를 비우면 옅은 단색이 깔린다.
- 홈에 보일 것: "짧은 글 탭" 켬·끔 하나.
  끄면 홈·서재 페이지에서 탭이 사라지고 긴 글만 보인다.
  (설정 키 이름 showShortNotes 는 저장된 설정과 맞추려고 그대로 둔다.
  섹션 순서 바꾸기는 두지 않는다. 홈은 시안 고정 배치다)
- 색: 개별 색상만 고른다. 테마 프리셋은 두지 않고, 대신 "쪽빛 색으로 되돌리기" 버튼을 둔다.
  이 버튼은 사이트 색과 서재·시리즈의 바탕·글자색만 되돌린다.
  서재 이름·짧은 이름·순서·소속 서재와 문구·서재 주인·템플릿은 건드리지 않는다.
  되돌리는 규칙:
    · 이름이 기본 서재와 같은 서재 → 그 기본 짝.
    · 이름이 다른 서재 → 파스텔 여섯 짝을 순서대로, 다른 서재가 쓴 짝은 피해서.
    · 시리즈 → 색을 비워 서재 색을 물려받게.
  누르면 바로 바꾸지 않고 "서재·시리즈 N개의 색이 이렇게 바뀝니다" 미리보기를 먼저 보여 준다.

## 묶어서 긴 글 초안 만들기
- 글관리의 **짧은 글** 탭에서 짧은 글 여러 개를 골라 누르면 Claude 가 긴 글 초안 한 편으로 엮는다.
- 템플릿을 고를 수 있다(안 고르면 자유 형식). 고른 템플릿의 뼈대를 따라 쓴다.
- 원본 짧은 글은 그대로 남는다. 지우거나 옮기지 않는다.
- 한 번에 20개, 본문 합계 20,000자까지.
- 만들어진 글은 published=false 초안. 서재·시리즈는 고른 짧은 글에서 가장 많은 이름을 쓴다.
- posts.source_note_ids 에 밑이 된 짧은 글 아이디를 적어 둔다.
  글관리에서는 "긴 글 초안으로 자람"으로 보이고, 방문자 요약 창에서는
  "이 글이 나온 짧은 글"로 보인다. 단, 공개된 것만 보인다.
- 만든 뒤 긴 글 수정 화면(/write/[id])으로 넘어간다. 발행은 평소처럼 거기서 한다.

## 모바일 우선
휴대폰(390px)을 기준으로 먼저 만들고, PC 는 폭만 넓혀서 대응한다.
- 홈(모바일): 커버+서재 주인 → 긴 글/짧은 글 탭 → 서재 고르기 + 앨범형·목록형 전환 →
  카드 목록 → 하단 고정 메뉴.
- 홈(PC): 같은 차례. 앨범형만 2열에서 3열로 넓어지고, 하단 고정 메뉴 대신 상단 메뉴를 쓴다.
- 앨범형: 표지 200px 2열, 표지 아래 제목과 "날짜 · 서재(또는 시리즈)".
- 목록형: 날짜·읽는 시간 / 제목 / 요약 첫 줄 + 오른쪽 88px 네모 표지.
- 서재 화면: 모바일은 전체 화면, PC 는 가운데 창.
- 요약 창: 모바일은 아래에서 올라오는 시트, PC 는 가운데 모달.
- 요약 창에 공유하기 버튼 (Web Share API, 안 되는 브라우저는 링크 복사).
- 검색은 아직 만들지 않는다. 시안의 돋보기 자리는 비워 둔다.

## 글쓰기 (/write)
- '글쓰기' 버튼 하나. 예전 빠른 메모(/memo)와 글쓰기를 한 화면으로 합쳤다.
  /memo 는 /write 로 넘어간다. 휴대폰 홈 화면 아이콘(PWA)도 /write 로 열린다.
  (아이콘의 id 는 예전 그대로 둬서 이미 추가해 둔 아이콘이 다른 앱으로 바뀌지 않는다)
- 열자마자 본문 입력칸에 커서. 맨 위에 **[짧은 글 | 긴 글]** 전환. 기본은 짧은 글.
- **서재·시리즈 고르기**(짧은 글·긴 글 같은 두 칸): '서재'(필수 아님, 비우면 분류 전)와 '시리즈'(선택).
  서재를 고르면 그 서재의 시리즈만 편수와 함께 보인다. 서재를 바꾸면 시리즈는 비운다.
  시리즈 칸에 없는 이름을 적으면 그 자리에서 그 서재 아래 시리즈로 만들어 설정에 저장한다(설정에 다녀올 필요 없음, 관리자만).
  같은 서재에 같은 이름이 이미 있으면 그것을 고른다. 글에는 시리즈 이름(없으면 서재 이름)이 저장된다.
  짧은 글에서는 시리즈 칸을 접어 두고 '시리즈 추가'를 눌러 펼친다. 태그는 없다.
- **짧은 글**: 본문 + 서재(시리즈)만. 기본은 비공개로 저장한다(기록이 먼저, 공개는 글관리에서 골라도 된다).
  입력칸 아래에 **[나만 보기 | 공개 + X]** 전환이 있다.
  - 기본은 늘 나만 보기. 고른 값은 기억하지 않는다(열 때마다, 그리고 '공개 + X'로 한 번 적고 나면 나만 보기로 돌아간다).
  - '공개 + X'를 고르면 버튼이 '적고 X에 올리기'로 바뀐다. 공개(published=true, visibility='public')로 저장하고
    공개 페이지를 새로 만든 **뒤에** X 글쓰기 창을 연다. 저장이 실패하면 X 창은 열지 않는다.
  - 창은 저장이 끝난 뒤에 연다(휴대폰 홈 화면 앱에서 빈 창을 먼저 열어 두는 방식은 불안정하다).
    팝업이 막히면 안내를 보여 주고, '오늘 쓴 짧은 글'의 공개된 줄마다 있는 'X에 올리기'로 다시 올릴 수 있다.
  - '오늘 쓴 짧은 글'의 '공개됨 / 나만 보기' 표시는 실제 공개 여부를 따른다.
  - 고치기(/write/[id])에는 이 전환이 없다. 공개 여부는 건드리지 않는다.
  입력칸 아래에 '오늘 쓴 짧은 글' 목록.
- **긴 글**로 바꾸면 제목·템플릿·서재·시리즈·표지·세 줄 요약 만들기·공개 설정이 펼쳐진다.
  쓰던 본문은 그대로 따라간다. 긴 글에서 짧은 글로 돌아갈 때는 제목·서식이 사라진다고 한 번 묻는다.
- 긴 글 저장은 임시저장(비공개) / 발행하기. 책 제목·카테고리·태그·책 소개 문구·예약 발행은 없앴다.
  (예약 발행은 화면에만 있고 서버가 받지 않던 칸이었다. 책장을 없애면서 책 제목도 필요 없어졌다)
- 기존 글 고치기는 /write/[id]. 그 글의 종류(짧은 글/긴 글)로 열린다. 종류는 거기서 바꾸지 않는다.
- 짧은 글은 관리자만 쓴다. 관리자가 아닌 글쓴이에게는 긴 글만 보인다.

## 글관리 (/notes)
- 이름은 글관리, 주소는 /notes 그대로(관리자만 쓰는 화면이라 주소를 흔들지 않는다).
- 맨 위 탭 **[짧은 글 | 긴 글]**. 탭마다 같은 필터(모두·분류 전·공개한 것·나만 보기·서재별)를 쓴다.
  서재별은 서재를 고르면 시리즈 글도 함께 나온다.
- **짧은 글 탭**: 공개하기 · 나만 보기로 · 서재 바꾸기 · X 공유 · 묶어서 긴 글 초안 만들기 · 삭제.
  각 줄의 '고치기'는 /write/[id] 로 간다.
  '서재 바꾸기'는 두 단계: 서재를 고르고 → 그 서재의 시리즈(또는 '서재에만 두기')를 고른다. 빈 시리즈도 보인다.
- **긴 글 탭**: 줄을 누르면 /write/[id] 로 수정. 여러 개 골라 공개 / 나만 보기 · 서재 바꾸기 · 삭제.
- 오른쪽 위에 글쓰기 버튼과 톱니바퀴(⚙, 설정). 설정 맨 아래에 로그아웃이 있다.

## X 공유
두 군데에서 같은 함수(lib/x-share.ts 의 xShareUrl·openXWindow)를 쓴다. X API 는 쓰지 않는다.
인텐트 주소에 본문과 적바림 원문 링크를 채워 새 창으로 열 뿐이다. 키·환경변수도 없다.
- **글관리**의 짧은 글 탭에서 짧은 글 하나를 골라 "X에 공유"를 누르면 X 글쓰기 창(웹 인텐트)이 열린다.
  누르면 그 짧은 글은 사이트에서도 공개로 바뀐다. 먼저 한 번 확인을 묻는다.
  (창은 클릭 안에서 바로 열고, 공개 전환은 그 뒤에 보낸다)
- **글쓰기**의 짧은 글에서 '공개 + X'로 적으면, 공개로 저장한 뒤에 같은 창이 열린다. 위 "글쓰기" 참고.
- 280자를 넘으면 앞부분만 넣고 "…" 와 링크를 붙인다.
- 짧은 글의 원문 주소는 긴 글과 같은 /posts/[id] 를 쓴다. 짧은 글이면 제목·표지 없이 본문만 보인다.

## 안정성
- Supabase 무료 플랜은 활동이 없으면 프로젝트가 일시정지된다. (실제로 멈춘 적 있음)
- keep-alive: Vercel Cron 이 하루 한 번 /api/keep-alive 를 불러 DB 에 가벼운 조회를 날린다.
  CRON_SECRET 환경변수로 보호한다. (Vercel 이 Authorization: Bearer <CRON_SECRET> 를 붙여 호출)
- 공개 페이지(홈·글)는 캐시 + 재검증(5분). 글·설정을 바꾸면 revalidatePath 로 즉시 새로 만든다.
  DB 조회가 실패하면 예외를 던져 재검증을 실패시킨다. 그래야 "빈 페이지"가 캐시를 덮어쓰지 않고
  마지막으로 성공한 페이지가 계속 보인다. (lib/supabase.ts 의 assertDbOk)
- 캐시되는 페이지는 로그인 여부를 알 수 없으므로 공개 글(published + visibility='public')만 싣는다.
  루트 레이아웃에서 auth() 를 부르지 않는다. 부르면 모든 페이지가 매 요청 동적 렌더링된다.
  로그인 상태는 브라우저에서 SessionProvider 가 가져오고, 수정·삭제 버튼도 브라우저에서 판단한다.
  (실제 권한은 API 가 다시 검사한다)
- 관리자 화면(글관리 /notes, /admin, 글쓰기 /write)은 캐시하지 않는다. 항상 지금 DB 상태를 본다.
