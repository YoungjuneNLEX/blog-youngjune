# 적바림 설계 (콘티 작업실)

> 2026-10-20 방향 전환: 공개 블로그 → 나만 쓰는 비공개 콘티 작업실.
> 옛 블로그 설계는 docs/JEOKBARIM-blog-archive.md 에 보관했다(참고용, 이 문서가 기준).

## 정체성
- 적바림은 영상(네이버 클립·유튜브)을 만들기 위해 나 혼자 쓰는 비공개 작업실이다.
- 글을 쓰는 곳이 아니라, 메모하고 자료를 모아 **콘티를 짜는 곳**이다.
- 방문자용 화면은 없다. 모든 화면은 로그인해야 보인다. 검색엔진에도 노출하지 않는다(noindex, robots 전체 차단).

## 기본 단위: 콘티(에피소드)
- 영상 한 편 = 콘티 한 장.
- 콘티는 채널(네이버 클립 | 유튜브), 템플릿, 날짜(자동), 상태를 가진다.
- 상태는 가볍게만: 준비 중 / 대본 완성 / 올림. 올린 뒤에는 영상 주소를 적어 둘 수 있다.
- 알림·마감·연속 기록 같은 압박 장치는 없다.

## 장면 카드
- 콘티는 장면 카드 #0, #1, #2… 가 순서대로 이어진 것이다.
- 카드 하나의 구성:
  - 안내 문구: 카드 맨 위 옅은 글씨 ("여기엔 오늘의 공부 문제를 쓰세요").
  - 화면 칸: 이미지·캡처·스케치·파일. 여러 개 가능.
  - 말 칸: 그 장면에서 할 대사.
  - 메모 칸(접혀 있음, 선택): 자막·편집 메모.
- 고정 문구 카드(인사말, 닫는 말)는 기본 문구가 미리 들어가 있고 수정할 수 있다.
  기본 문구는 설정에서 바꿀 수 있다.
- 카드 순서 바꾸기, 카드 추가·삭제 가능. 선택 카드는 비워 두면 대본에서 빠진다.

## 템플릿 ① 네이버 클립 — 도산 공부 기록 (타겟 50~60대, 주제: 개인회생·파산, 상속파산, 법인회생·파산)
- #0 인사말 (고정 문구, 예시: "안녕하세요, 사무장 박영준의 도산 공부 기록입니다.")
- #1 오늘의 공부 문제 (= 제목. 내가 나에게 낸 공부 문제)
- #2 내가 아는 것 (지금의 이해, 틀려도 됨)
- #3 찾아본 것 (법조문·판례·실무 자료 + 출처, 여러 개)
- #4 실무에서 본 것 (개인정보·사건 식별 정보 넣지 않기)
- #5 한 줄 정리 ("법은 이렇게 정해두었다")
- #6 닫는 말 (고정 문구, 필수): "오늘 공부한 기록이고, 절대적이지 않으니 정확한 것은 전문가 상담이 필요합니다."
- #7 다음 공부 문제 (말 칸만. 적으면 질문 주머니에도 들어간다)

## 템플릿 ② 유튜브 — 법무사 수험 기록
- #0 인사말 (고정 문구)
- #1 오늘 공부 (과목 · 공부한 범위)
- #2 오늘 고른 주제 (중요하거나, 재밌거나, 실무 경험과 겹치는 것)
- #3 문제
- #4 풀이 과정
- #5 실무와 부딪힌 지점
- #6 (선택) 책에서 길어 올린 생각: 책 정보 / 건진 표현 / 생긴 궁금증 / 법으로 찾아본 것 / 사유 한 줄
- #7 닫는 말 (고정 문구, 필수, 클립과 같은 기본 문구)
- #8 다음 공부 문제
- 배경 영상은 실제 공부 장면. 서사는 불평이 아니라 감사와 결단.

## 대본 모드
- 말 칸만 순서대로 이어 큰 글씨로 보여준다. 녹음할 때 휴대폰을 세워 두고 읽을 수 있게.
- 화면 꺼짐 방지(Wake Lock), 글자 크기 조절, 장면 번호 표시.
- 편집 모드에서는 화면 칸을 함께 보며 장면을 붙일 수 있게 "콘티 보기"(화면 + 말 나란히)도 둔다.

## 첨부
- PC: 이미지·파일을 카드에 끌어다 놓으면 바로 걸린다.
- 어디서든: 클립보드 붙여넣기(캡처 → 붙여넣기)로 이미지가 바로 걸린다.
- 휴대폰: 버튼 하나로 사진 찍기 / 갤러리에서 고르기.
- 이미지는 카드 안에서 바로 미리보기, 누르면 크게. PDF 등 파일은 파일 카드로 걸리고 누르면 열린다.
- 이미지는 올리기 전에 적당히 줄여서(긴 변 약 2000px) 올린다. 원본이 필요하면 원본 유지 옵션.
- 저장은 Supabase Storage 비공개 버킷 + 서명된 주소(signed URL). 공개 버킷 금지.

## 스케치북 (아이패드 + 애플 펜슬)
- 화면 칸의 "스케치" 버튼 → 하얀 종이가 화면 가득 열린다.
- 도구는 펜, 지우개, 되돌리기, 색 서너 가지만. 필압 반영.
- 펜(pointerType=pen)으로만 그리고, 손가락은 화면 이동·확대. 손바닥 오입력 방지.
- 닫으면 이미지(PNG)로 화면 칸에 걸린다. 획 데이터(JSON)도 함께 저장해 다시 열어 이어 그릴 수 있게.
- 도형·레이어·무한 캔버스는 만들지 않는다. 복잡한 그림은 다른 앱에서 그려 끌어다 넣는다.
- 욕심 목록(지금은 안 만듦): 그린 순서를 재생하는 타임랩스.

## 질문 주머니
- 손님에게 들은 질문을 한 줄씩 넣는 곳. 상담 끝나고 휴대폰으로 10초면 넣을 수 있게.
- 항목: 질문 / 내가 한 답변 요약(선택) / 날짜(자동) / 분야(선택).
- 입력 칸 안내 문구에 박아 둔다: "질문만 적어 주세요. 손님 이름·연락처·사건 정보는 적지 않습니다."
- 홈(콘티 목록) 맨 위에 주머니의 질문 하나가 흐린 글씨로 뜬다. 열 때마다 다른 질문.
  - 누르면 그 질문이 "오늘의 공부 문제"에 들어간 새 콘티가 열린다(채널 선택).
  - 넘기거나 무시하면 그냥 사라진다. 아무 기록도 남기지 않는다.
- 콘티의 "다음 공부 문제"도 주머니에 들어간다.
- 콘티로 만든 질문에는 "콘티로 만듦" 표시만 붙는다(지우지 않음).
- 적바림이 나에게 "오늘 공부했니?" 같은 질문을 던지는 기능은 만들지 않는다.

## AI 점검 (동료 역할)
- 기존 api/proofread.js 의 호출 방식과 ANTHROPIC_API_KEY 재사용. admin 만 호출 가능.
- 대상: ① 질문 주머니의 내 답변 ② 콘티의 말 칸·찾아본 것.
- 언제: 질문 주머니는 저장 후 내용이 바뀌었을 때만 한 번 조용히 점검. 콘티는 "점검하기" 버튼으로.
  (자동 저장마다 호출하지 않는다 — 비용)
- 점검 항목:
  - 사실 오류로 보이는 내용 (예: "주민등록초본은 법원에서 뗀다")
  - 지시형 표현("당신은 이렇게 하세요"), 단정 표현(예: "모든 재산")
  - 출처 없는 법 내용, 닫는 말 누락
  - 개인정보·사건 식별 정보로 보이는 내용
- 결과는 해당 문장 옆 작은 표시로: 문제 된 문장 / 이유 / 근거 / 고칠 제안.
- 근거는 법령명·조문 번호 등으로 적고, 링크는 지어내지 않는다(국가법령정보센터 검색으로 이어주는 정도만).
- 확신이 없으면 맞다·틀리다 대신 "확인 필요"로만 표시한다. 법 내용을 새로 지어내지 않는다.
- 자동으로 덮어쓰지 않는다. 적용 / 무시는 내가 고른다.

## 안전선 (변호사법) — 화면 안내와 AI 점검 모두 이 기준
- 주어는 언제나 "나의 공부". 지시형 금지.
- 단정적 처방 대신 "제도는 이렇게 설계돼 있다"는 설명 톤.
- 출처는 법조문 우선. 닫는 말은 매 편 필수.

## 빠른 메모
- 유지. 제목 없이 바로 적는 입력창.
- 메모를 콘티의 특정 카드(찾아본 것 / 실무에서 본 것 등)로 옮길 수 있다.

## 화면 구성
- 하단 메뉴: 콘티 · 질문 · (+ 새 콘티) · 메모 · 설정. 가운데 + 버튼이 가장 크다.
- 홈 화면 아이콘(PWA)으로 열면 콘티 목록이 바로 뜬다.
- 콘티 목록: 최신순, 채널별 보기, 상태 표시. 맨 위에 질문 주머니의 흐린 제안.
- 입력 중 자동 저장 + 기기 임시 저장(기존 짧은 글 임시 저장 방식 재사용).

## 디자인
- 콘셉트: 깨끗한 노트. 오래 머물러도 편안한 공간. 장식보다 여백.
- 색 (토큰으로 정의, 설정에서 미세 조정 가능):
  - 바탕: 따뜻한 흰색 #fdfcf9 / 카드: #ffffff
  - 본문 글자: 먹색 #2b2b2b / 보조 글자: #6b6b6b (대비 확보, 이보다 옅게 하지 않기)
  - 노트 줄·구분선: #ece9e2
  - 강조색은 하나만: 연한 쪽빛 계열(예: #3f5f7f). 버튼·선택 상태에만.
  - 경고(AI 점검 표시): 부드러운 황토색(예: #b8862b), 빨강 남용 금지.
- 글꼴: UI는 IBM Plex Sans KR(또는 Pretendard), 대본 모드는 읽기 편한 글꼴로 크게.
- 입력 칸 아래 아주 옅은 줄로 노트 느낌.
- 버튼: 자주 쓰는 동작은 화면 아래쪽(엄지 닿는 곳). 터치 영역 48px 이상. 한 화면에 버튼 최소한.
- 모바일 우선(390px 기준) → 아이패드(펜 입력) → PC 순으로 넓힌다.
- 다크 모드는 지금은 만들지 않는다.

## 안정성
- Supabase 무료 플랜은 활동이 없으면 프로젝트가 일시정지된다. (실제로 멈춘 적 있음)
- keep-alive: Vercel Cron 이 하루 한 번 /api/keep-alive 를 불러 DB 에 가벼운 조회를 날린다.
  CRON_SECRET 환경변수로 보호한다. (Vercel 이 Authorization: Bearer <CRON_SECRET> 를 붙여 호출)
- 공개 페이지(홈·글)는 캐시 + 재검증(5분). 글·설정을 바꾸면 revalidatePath 로 즉시 새로 만든다.
  DB 조회가 실패하면 예외를 던져 재검증을 실패시킨다. 그래야 "빈 페이지"가 캐시를 덮어쓰지 않고
  마지막으로 성공한 페이지가 계속 보인다. (lib/supabase.ts 의 assertDbOk)
- 캐시되는 페이지는 로그인 여부를 알 수 없으므로 공개 글(published + visibility='public')만 싣는다.
  루트 레이아웃에서 auth() 를 부르지 않는다. 부르면 모든 페이지가 매 요청 동적 렌더링된다.
  로그인 상태는 브라우저에서 SessionProvider 가 가져오고, 수정·삭제 버튼도 브라우저에서 판단한다.
  (실제 권한은 API 가 다시 검사한다)
- 관리자 화면(글관리 /notes, /admin, 글쓰기 /write)은 캐시하지 않는다. 항상 지금 DB 상태를 본다.
- 단, 방문자 화면이 없어졌으므로 "공개 페이지 캐시"는 더 이상 필요 없다. keep-alive Cron 은 유지.

## 하지 않을 것
- 공개 발행, 방문자 화면, SEO, 댓글.
- 발행 일정, 알림, "N일째 안 올림" 같은 압박 장치. 적바림이 나에게 숙제를 묻는 기능.
- 영상 편집·업로드 자동화 (영상은 내가 직접 만든다). AI 성우.
- 복잡한 그림판(레이어·도형·무한 캔버스).
- 기존 글 데이터 삭제 (보관만).
